# Neoart Import Studio — редизайн UI и редактора

> Дата: 2026-07-03 · Ветка: `dev`
>
> Модернизация страницы «Импорт Neoart» и переработка редактора карточки по
> фидбеку пользователя: современный вид, кликабельные карточки, центрированная
> крупная модалка, понятные подписи, редактируемые поля, живой предпросмотр
> конструктора, и фикс багов редактора (дублирование Cropper, выход за модалку).

## 1. Контекст

Базовая фича (импорт/нарезка/ревью/публикация) уже работает (спека
`2026-07-02-neoart-import-studio-design.md`). Текущий редактор — черновой:
- правая колонка всегда показывает **оба** превью (каталог+конструктор) — путает;
- `setMode` пересоздаёт `Cropper` с двойным вызовом `img.onload` (вручную +
  событием) без надёжного `destroy()` → контейнеры Cropper **штабелируются**
  (дублирование при переключении режимов);
- нет ограничения высоты → картинка выходит за модалку;
- модалка вверху, не по центру;
- технические подписи (listimg/imgconst/raw/crop);
- поля (ширина/цена/остаток/секция) — только текст, не редактируются.

Файлы: `admin/view/neoart_import.php` (разметка+модалка), `admin/assets/js/neoart_import.js`
(`NeoartUI`), `admin/index.php` (подключение ассетов). Референс живого конструктора —
`constructor_baget/block_2_maket.php` (рамка из 4 полос `repeat-x`, боковые повёрнуты 90°).

## 2. Зафиксированные решения

- **Флаги** (`cut_flags`: notwhite/tiny/no-window) — показываем **только для чтения**
  (подсказка, почему товар «Требует правки»); редактируемые поля — ширина,
  без четверти, цена, остаток, секция.
- **Сохранение**: кнопка «Сохранить» сохраняет редактируемые поля; обрезки картинок
  сохраняются своими кнопками; загрузки применяются сразу.
- **Живой предпросмотр конструктора** — клиентский: текущая обрезка Cropper'а
  (`getCroppedCanvas()`) подставляется в 4 полосы `repeat-x` (как `imgconst` в
  `block_2_maket.php`), обновление по событию `crop` (троттлинг). Финальный
  сохранённый файл по-прежнему режет сервер (GD) из того же прямоугольника, так что
  превью ≈ результат.
- Современный вид достигается доп. CSS `admin/assets/css/neoart_import.css` +
  чистой Bootstrap-5 разметкой; без сторонних UI-библиотек (только уже подключённые
  Bootstrap/Cropper).

## 3. Страница «Импорт Neoart» — модернизация

- **Тулбар** в карточке с тенью: слева выбор каталога, справа кнопки-шаги
  «1 Скачать базу», «2 Нарезать картинки», «Обновить список»; прогресс-бары
  скрыты (`d-none`) пока процесс не идёт, показываются при запуске.
- **Фильтры** — сегментированная pill-группа (Все / Требуют правки / Готовы /
  Уже в каталоге) + поле поиска с иконкой; «Одобрить выбранные» справа.
- **Карточки** — современная сетка: скругление, мягкая тень, ховер-подъём,
  крупное превью каталога сверху, компактные бейджи статуса, строка параметров,
  кнопки «Одобрить/✕» внизу. **Вся карточка кликабельна → открывает редактор**;
  клики по кнопкам «Одобрить/✕» и чекбоксу выбора вызывают `stopPropagation`
  (не открывают редактор). Класс-контракт остаётся: `.neoart-card[data-id]`,
  `.neoart-approve`, `.neoart-reject`, `.neoart-select` (+ новый `.neoart-open`
  как маркер зоны открытия — необязателен, т.к. весь корпус карточки открывает).
- XSS-дисциплина сохраняется (`esc()` на всех полях из фида).

## 4. Модалка — по центру, крупнее

`modal-dialog modal-xl modal-dialog-centered modal-dialog-scrollable`. Тело с
внутренним скроллом; редактор Cropper ограничен по высоте (`max-height: 60vh`,
ширина 100%), картинки не выходят за пределы.

## 5. Редактор — переработка

Две колонки: **слева** один Cropper (обрезка), **справа** — предпросмотр **только
активного режима** + редактируемые поля.

### Режимы (вкладки с понятными названиями)
- **«Картинка для каталога»** — Cropper с соотношением 150/100; справа —
  **мок карточки каталога** (`<img>` 150×100 + «Арт.» + цена), обновляется в
  реальном времени из `getCroppedCanvas()` по событию crop.
- **«Картинка для конструктора»** — Cropper свободный (полоса профиля); справа —
  **живая рамка конструктора**: фикс-бокс с 4 полосами (верх/низ `repeat-x`
  горизонтально, левая/правая — повёрнуты 90°), фон каждой — dataURL текущей
  обрезки; обновление по crop (троттл ~100 мс). Повторяет алгоритм
  `block_2_maket.php`, поэтому менеджер видит, как реально сложится багет.

### Один Cropper без дублирования (фикс)
`setMode(mode)`:
1. если есть `_edit.cropper` → `destroy()` и обнулить;
2. установить `img.src` (исходное фото) и обработчик `load` **один раз** через
   `img.onload = fn` (или `addEventListener('load', fn, {once:true})`); НЕ вызывать
   `onload()` вручную — если фото уже в кэше, инициализировать Cropper через
   `requestAnimationFrame`/микротаск после присвоения src, но строго один раз;
3. `new Cropper(img, {viewMode:1, autoCropArea:0.6, aspectRatio: mode==='listimg'?150/100:NaN})`
   с обработчиком `crop` → обновление предпросмотра активного режима (троттл).
Гарантия: в DOM всегда ровно один `.cropper-container`.

**Внутренние ключи режима остаются `'listimg'`/`'imgconst'`** (совпадают с параметром
`which` эндпоинтов `item_save_crop`/`item_upload` — их контракт НЕ меняется); меняются
только видимые подписи. Так публикация и серверная нарезка не затрагиваются.

### Понятные подписи (старое → новое)
- «Каталог (listimg)» → **«Картинка для каталога»**
- «Конструктор (imgconst)» → **«Картинка для конструктора»**
- «Сохранить кроп» → **«Сохранить обрезку»**
- «Загрузить listimg» → **«Загрузить свою картинку каталога»**
- «Загрузить imgconst» → **«Загрузить свою для конструктора»**
- «Загрузить raw» → **«Заменить исходное фото»**
- «Авто-нарезка заново» → **«Пересобрать автоматически»**
- «Превью listimg (150×100)» → **«Как будет в каталоге»**
- «Превью imgconst (repeat-x)» → **«Как будет рамка в конструкторе»**

### Редактируемые поля + сохранение
Справа — поля ввода: **Ширина, мм** (`width_mm`), **Без четверти, мм**
(`widthwithout_mm`), **Цена, ₽** (`price_final`), **Остаток** (`storage`),
**Секция** (`section_name`, текст). **Флаги** — только для чтения. Кнопка
**«Сохранить»** шлёт в новый `item_update.php`.

## 6. Новый эндпоинт `admin/request/neoart/item_update.php`

POST `id`, `width_mm`, `widthwithout_mm`, `price_final`, `storage`, `section_name`.
Валидация (числа ≥ 0; секция — строка ≤ 255), prepared UPDATE
`neoart_item SET ... WHERE id=?`, `updated_at`. Ответ `{ok:1}` (JSON_UNESCAPED_UNICODE).
Правки уедут в `catalog_baget` при одобрении — `item_approve.php` уже читает
`width_mm/widthwithout_mm/price_final/storage` из `neoart_item` (секция в каталог не
переносится — колонки нет; поле нужно менеджеру для сверки/поиска в staging).

## 7. Файлы

**Создаётся:**
- `admin/assets/css/neoart_import.css` — современные стили страницы/карточек/модалки/рамки-превью.
- `admin/request/neoart/item_update.php` — сохранение редактируемых полей.

**Модифицируется:**
- `admin/view/neoart_import.php` — модернизированный тулбар/фильтры/сетка + переработанная модалка (центр, xl, скролл, режимы, поля, два блока живого превью).
- `admin/assets/js/neoart_import.js` — новый `cardHtml` (кликабельная карточка), переработанные `openEdit/setMode/saveCrop/upload/resetCut` (один Cropper, живые превью, троттл), новый `saveFields`, обновлённые подписи/бинды.
- `admin/index.php` — подключить `neoart_import.css`; бамп версий ассетов.

## 8. Обработка ошибок / крайние случаи

- Живой предпросмотр не должен тормозить UI: событие `crop` троттлится; генерация
  canvas — только для активного режима.
- Пустая/некорректная обрезка → кнопка «Сохранить обрезку» шлёт координаты
  `getData(true)`; сервер уже клампит прямоугольник (готово).
- `item_update` с нечисловыми значениями → 400 + `{error}`; UI показывает toastr.
- Модалка `scrollable` — длинный контент не выходит за экран.

## 9. Вне охвата (YAGNI)

- Изменение публичного конструктора/каталога сайта — не трогаем.
- Drag-and-drop загрузка, кроп-хоткеи, undo — не сейчас.
- Редактирование флагов, массовое редактирование полей — не сейчас.
- Смена схемы `publicvendor` — отдельное решение (известное ограничение).
